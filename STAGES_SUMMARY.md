Here is a comprehensive summary of the planning and development documents generated for the **CivicVoice** platform so far, formatted as a quick-reference table for stakeholders and development teams.

### **CivicVoice Documentation Summary**

| Stage / Document | Primary Objective | Key Components & Features | Core Outcomes & Developer Instructions |
| :--- | :--- | :--- | :--- |
| **Concept & Master Roadmap** | To outline the overall vision, purpose, and 12–18 month development timeline of the platform. | - Issue Builder & Evidence Vault <br>- Smart Authority Mapping <br>- Communication Engine (Emails/Scripts) <br>- 6-Phase Rollout Plan | Establishes the core value proposition: bridging the gap between frustrated citizens and complex corporate/statutory legal processes. |
| **Stage 1: Requirements & User Stories** | To define exactly *who* the software is for and *what* it must do before any design or coding begins. | - **Personas:** Citizen, Tenant, Advocate.<br>- **Epics:** Account Management, Issue Setup, Evidence Vault, Comms Generator, Tracking Dashboard.<br>- **NFRs:** Mobile-first, WCAG 2.1 AA accessibility, <2.5s load times. | Provides the "Blueprint" for the project. Translates abstract ideas into actionable "User Stories" (e.g., *“As a user, I want...”*) for the development queue. |
| **Stage 2: Legal, Compliance & Risk Assessment** | To protect the platform and its founders from legal liability, GDPR fines, and defamation lawsuits. | - **GDPR:** Right to be forgotten, data minimization.<br>- **Liability:** "Not Legal Advice" disclaimers, Acceptable Use Policy.<br>- **Defamation Shield:** 1-to-1 private email routing (no public forum posting). | Mandates strict database separation of User PII and Case Data. Defines Terms of Service requirements prior to launch. |
| **Stage 3: Data Architecture & Content Strategy** | To map the statutory rules, authority contacts, and dynamic text logic that powers the platform's core engine. | - **Authority DB:** Spreadsheets mapping specific issues to correct bodies (e.g., HSA, EPA, RTB).<br>- **Templates:** JSON/Logic-based "Mad-Libs" structures for legal emails.<br>- **Scripts:** De-escalation & rebuttal scripts for in-person confrontations. | Directs the content team to scrape government websites for contacts and map specific hazards to Irish statutory laws (e.g., *Safety, Health & Welfare at Work Regs*). |
| **Stage 4: UI/UX Prototyping & User Journey** | To design the visual interface and map the step-by-step path a user takes to report an issue. | - **User Flow:** 5-step path (Intake -> Geolocation -> Vault -> Action Center -> Dispatch).<br>- **Wireframes:** Dashboard, Wizard, Action Center.<br>- **Design System:** Trust-building colors (Navy/Teal), highly legible typography. | Instructs the UI Designer to build a clickable Figma prototype and outlines the testing script to run with real users before coding begins. |
| **Stage 5: Technical System Design & Architecture** | To define the exact software stack, cloud infrastructure, and security protocols required to build the platform. | - **Tech Stack:** Next.js (Frontend), Node.js (Backend), PostgreSQL (DB), Prisma.<br>- **Infrastructure:** Vercel, AWS (EC2, RDS, S3 for Evidence Vault).<br>- **Security:** AES-256 encryption, malware scanning for uploaded evidence. | Hands off the project to the CTO/Lead Developer to provision servers, design the SQL database schema, and begin "Sprint 0" (setting up coding environments). |

**Current Status:** The project is now fully planned and documented. The next step is to transition into **Stage 6: Project Planning & Sprint 0**, where these documents are converted into Jira/Trello tickets, and actual software coding begins.
